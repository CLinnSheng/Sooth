# Protocol invariants

The properties the Sooth contracts must keep true. Each row names the code that protects it and a test that exercises it, or says "not tested yet". Written from `contracts/src` and `contracts/test`.

## Status of testing

- Tests named `invariant_*` are stateful invariant tests. Every other test named below is a unit test or a single-sequence fuzz test (one scenario, or one fixed order of calls with fuzzed amounts).
- The stateful suite is in `contracts/test/invariant/`: `SoothInvariants.t.sol` (the `invariant_*` functions and `afterInvariant`), `MarketHandler.sol` (AMM, order book, EOA arbitrator, redeem, withdrawals, transfers, donations, clock edges) and `ResolverHandler.sol` (propose, dispute, finalize, rule, refund, challenge-window edges). Setup, run counts and the ghost-counter rule are in [`testing.md`](testing.md) sections 1 and 2.
- These rows have a stateful invariant: INV-COL-1, -2, -3, -5, -6, INV-TIME-2, INV-RES-1, -2, INV-RED-1 to -4, INV-BND-1, -4, -5, -7, INV-OB-1 to -5. Other rows marked "not tested yet" are single-call checks and need a plain unit test.
- Mutation checks for the invariants are in [`testing.md`](testing.md) section 3.
- A "Test" cell names a test that touches the invariant, not one that proves it for all call sequences. Where a test checks only part of a statement, "Notes" says which part.
- `test_RevertWhen_ResolvingTwice` exists in both `MarketResolution.t.sol` and `ChainlinkResolver.t.sol`, so those rows give the file.

## Terms

- **Backing**: `collateral.balanceOf(market) - accruedFees`, the collateral that backs outcome shares.
- **Settled**: `Market.state()` is `Resolved` or `Cancelled`.
- **Deadline**: `Market.resolutionDeadline() = closeTime + RESOLUTION_WINDOW` (7 days).
- `state()` is derived from the clock while `_state == Open`: `Open` before `closeTime`, `Closed` from `closeTime` up to but not including the deadline, `Cancelled` from the deadline on. `resolve` writes `_state = Resolved`.

| ID | Statement | Protected by | Test | Notes |
|---|---|---|---|---|
| INV-OB-1 | For each token id, the book's ERC-1155 balance equals the sum of `remaining` over its open listings. `cancel` works in every market state and returns exactly `remaining` to the seller. | `list` (escrow after insert), `_take` (`remaining -= fill` before paying), `cancel` (`remaining = 0`, unlink, return). | `invariant_OB_1_escrowEqualsOpenListings`; `testFuzz_ConservationAcrossRandomActions` | The handler sends no shares to the book directly. Such shares would make the balance greater and could never be taken out. |
| INV-OB-2 | Each (market, outcome) book is a doubly linked list sorted by price ascending, oldest first at equal price. `prev`/`next` agree both ways, `head`/`tail` are the first and last listing, every open listing is in its book, and a closed listing has `prev = next = 0`. | `_insert`, `_unlink`. | `invariant_OB_2_booksSortedFifoAndLinked`; `test_Buy_OldestFirstAtEqualPrice`; `test_Cancel_MiddleReturnsSharesAndRelinks` | `head` and `tail` have no getter; the invariant reads them from storage (`_books` is slot 2). |
| INV-OB-3 | The book never holds collateral. | `_take` (pays the seller straight from the buyer with `safeTransferFrom`). | `invariant_OB_3_bookHoldsNoCollateral`; `testFuzz_ConservationAcrossRandomActions` | |
| INV-OB-4 | What buyers pay equals what sellers receive. A fill takes the cheapest listings first, oldest first at equal price, at most `maxListings`, and costs `ceil(fill * price / 1e6)` per listing. | `buy`, `_canFill`, `_fill`. | `invariant_OB_4_buyersPayExactlyWhatSellersReceive`; `test_Buy_SweepPaysEverySellerExactly`; `test_Buy_RoundsCostUpSoNoFillIsFree` | The handler models each fill before the call and compares shares, cost and every trader's balance change (a buyer may fill their own listing). |
| INV-OB-5 | `list` and `buy` succeed only while the market is `Open`. | `_requireOpen`. | `invariant_TIME_2_tradingOnlyWhileOpen`; `test_RevertWhen_TradingAtClose_CancelStillWorks`; `test_RevertWhen_TradingAfterResolve_CancelStillWorks` | Checked with INV-TIME-2. |

## Known gaps in the documented behaviour

- [`trading-engine.md`](trading-engine.md) says initialisation "verifies its actual YES/NO balances exactly match the recorded reserves". `Market.initialize` only checks the collateral balance (`balance < initialLiquidity` reverts) and then mints the pools. This file follows the code.
- `OptimisticResolver` pushes bonds (the `@dev shortcut` comment in the contract). A bond token that blocks a recipient makes that settlement revert. That is outside these invariants and is not tested.
